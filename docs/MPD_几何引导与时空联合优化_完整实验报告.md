# MPD 几何引导与时空联合优化：完整实验报告

**日期**：2026-11-04
**分支**：`experiment/mpd-firsthit-geometry`
**起点冻结**：标签 `baseline/pre-mpd-geometry-guidance`（commit `799f3ff`）
**任务集**：20 个 N=4 冻结任务（`plan_bank_n4.json`，未增删）
**评测**：p ∈ {0, 0.05, 0.1, 0.2}，3 个评测种子 × 200~300 次 MC

---

## 0. 必须先把话说清楚的结论

> **First-Hit 几何引导能在 DDIM 去噪过程中真实改变轨迹，并且在"同一套候选选择程序"下
> 显著优于纯 SDF 引导（p=0.1 碰撞率 46.1% vs 55.3%，有效率 40% vs 20%）。
> 但它没有把系统带到最强纯时间基线（冻结库 + W2+，4.45%）附近，差距是数量级的。**

| 问题 | 真实回答 |
|---|---|
| 一、几何引导能改变扩散轨迹吗？ | **能**。同一初始噪声下路点平均位移 0.17–0.29 m，最大 1.4 m；梯度非零且方向经有限差分验证 |
| 二、几何 + 等待是否优于最强纯等待 W2+？ | **否**。G3 的 46.1% 远高于 W2+ 的 4.45% |
| 三、p=0.2 下碰撞率降低多少？ | G5 → G3：70.2% → 63.1%（−7.1 pp）。但 W2+ 在 p=0.2 是 36.8%，仍远好于两者 |
| 四、收益的代价？ | 轨迹长度 8.49 → 12.07 m（+42%），速度合规率 100% → 65%，规划耗时 +65% |
| 五、真 DDIM 引导是否优于候选重排序/后处理？ | **优于同条件的候选重排序**（G3 vs G5，−9.2 pp），但**都远不如冻结库** |
| 六、是否值得作为论文核心方法？ | **目前不足以作为核心方法**。可以作为"扩散过程内可微风险引导可行且有正收益"的方法学证据，但不能宣称它解决了多机器人延迟鲁棒问题 |

**为什么几何引导打不过纯等待**：真正的瓶颈不在几何，而在**规划覆盖率**。
4 台机器人**独立**从单机器人预训练模型采样时，几乎不可能同时满足 p=0 安全：
原始采样（B=1）的联合有效率是 **0%**；即使 8 候选 + beam 搜索，也只有 40%。
而冻结轨迹库是用"逐对增量构造 + 回溯"从 8 候选/机器人里挑出来的，
其对偶问题是**组合搜索**，不是**生成**。几何引导改进了生成，但改不动选择的天花板。

## 1. 研究目标与已有基础

### 1.1 为什么从纯等待走到几何—时间联合

前序实验（`docs/MPD_W2Plus_公平对照报告.md`、`docs/MPD_HighDelay_鲁棒性报告.md`）确认：

- 冻结库 + W2+@800 在 p=0.1 把碰撞率压到 **4.45%**；
- p=0.2 下即使按 p=0.2 重新优化，仍有 **20.88%** 残余；
- 残余不是预算问题（12→24 时隙无变化），而是"同一时刻两条路径相交、无论谁先谁后都会撞"。

这正是需要几何介入的依据：如果路径本身不在同一处相交，时间就不必硬扛。

### 1.2 本次的方法学发现（先说，因为它决定了一切）

**首次碰撞概率在路径重叠时恒等于 1，梯度为 0。**

N=2 冒烟测试中两机的同时刻最小间距是 **0.124 m**（d_safe = 0.35 m），
First-Hit DP 的软风险直接饱和到 `1.000`，`grad_norm` 恰好为 `0.0`——几何引导完全失效。

这不是实现 bug，而是**数学性质**：首碰概率是 96 个时隙的生存概率乘积，
任何单步碰撞概率 > 0 都会让累积值趋近 1；而软核 `sigmoid((d_safe−d)/T)`
在 `d ≪ d_safe` 时已经饱和。

**处理方式（不改动 First-Hit DP 的定义）**：
保留 `R_FH` 作为**评价**指标，另加一个**同刻最小间距铰链**作为可微几何代理：

```
L_geo = mean_{i<j, t} relu( d_safe + margin − ‖q_i(t) − q_j(t)‖ )
```

其中 `q_i(t)` 用与 First-Hit **完全相同**的时间映射（含基准发车间隔 stagger=3）取点。
这个铰链在深度重叠时每个时隙都有正梯度，不会饱和。

## 2. 方法设计

### 2.1 多机器人同步 DDIM

官方 MPD 的 `run_inference(n_samples=B)` 会把**同一组**起终点复制 B 份——
B 是候选数，不是机器人数。本实现把批次组织成 `B*N`：

```
batch index = b * N + i        （b = 候选, i = 机器人）
```

每台机器人有独立的 `qs_normalized = [start_i, goal_i]`（4 维条件），
共享同一去噪时间步；梯度通过**联合风险**在机器人之间耦合。

| 项 | 取值 |
|---|---|
| 可学习控制点 K | 16（+6 固定 = 22 个 B-spline 控制点） |
| 稠密采样 | 128 点 |
| 执行航点 | H = 32（等弧长重采样） |
| 扩散步数 | 15（DDIM） |
| 每步 Guide 更新 | 10 次 |
| 基准发车间隔 | 3 时隙 |

### 2.2 坐标与单位（问题 B）

| 空间 | 变换 | 代码 |
|---|---|---|
| 官方 [-1,1]² | `meters = (q + 1) * 5` | `official_to_meters` |
| 米制 [0,10]² | `official = q/5 - 1` | `meters_to_official` |
| 128 → 32 | **可微**等弧长重采样 | `resample_arc_length_diff` |

`searchsorted` 得到的索引是离散量（不可导，符合预期），但插值权重与端点可微，
梯度能传回控制点。最终真实执行评估用同一套航点，保证几何含义一致。

### 2.3 引导损失

```
L = λ_R · R_FH^soft + λ_D · L_hinge + λ_T · T_finish
```

- `R_FH^soft`：既有 First-Hit 软风险（**定义未改动**）；
- `L_hinge`：同刻最小间距铰链（新增，非饱和）；
- `T_finish`：完成时间代价。

官方 SDF Guide 通过 `SumGuide` 与几何 Guide 相加，权重各 1.0，**复用官方原生实现**。

| 参数 | 值 | 依据 |
|---|---|---|
| λ_R | 1.0 | 与等待优化一致 |
| λ_D | **800**（粗筛 50/200/800 中最好） | 见 §4 |
| λ_T | 0.05 | 与 `guidance.yaml` 一致 |
| 步长 / 裁剪 | 官方默认（lr=1.0，max_perturb_x=0.15，clip_grad value=1） | 未改 |

### 2.4 梯度符号与有效性（问题 A）

官方契约：`guide` 必须返回 **−∂L/∂cp**，DDIM 内部按 `x ← x + lr·guide` 更新。

验证证据：

| 检查 | 结果 |
|---|---|
| Guide 内部打开梯度（`torch.enable_grad` + `requires_grad_`） | ✅ 与官方 `cost_guides.py` 一致 |
| `grad_norm` 非零 | ✅ 1.57（N=2 冒烟）；20 任务均非零 |
| 有限差分方向一致性 | ✅ 见 `mpd_extension/test_first_hit_guide.py`（沿用前序的符号自检） |
| 引导是否真的进入状态更新 | ✅ 同种子配对位移 0.17–0.29 m（见 §6.4） |

## 3. 实现与调试历程（如实记录）

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 1 | `linear(): input must be Tensor, not None` | context 键名错：应为 `qs_normalized`，我先传了 `qs` | 改为走官方 `create_data_sample_normalized` |
| 2 | `Expected all tensors on same device` | `ee_pose_goal` 建在 CPU | 统一到 `starts.device` |
| 3 | `stack expects equal size`（beam search） | 单机器人时无机器人对，DP 无法计算 | 候选 <2 台时风险记 0 |
| 4 | `Sizes must match at dim -2` | `q_pos_start` 我传成 `[B,2]`/`[B,1,2]` 都不对 | 官方约定 **`[B,2]`**（实测确认） |
| 5 | `element 0 does not require grad` | DDIM 传入的 `x` 不带梯度 | Guide 内部自建 `requires_grad_`（官方做法） |
| 6 | 风险恒为 1.0、梯度恒为 0 | **软风险在路径重叠时饱和** | 新增同刻间距铰链（§1.2） |
| 7 | softmin 铰链也饱和（−τ·log H 处梯度为 0） | 数学性质 | 改为对时间取均值的 relu |
| 8 | cuDNN "unable to find an engine"（batch 24/32） | 官方 conv1d 在特定批大小下失败 | 候选分块（`--chunk 4`），数学不变 |

**无效尝试（记录在案）**：

- 只加 `λ_R` 的首版 Guide：梯度 0，轨迹完全不变 → 说明必须换非饱和代理；
- softmin 形式的铰链：在深度重叠时同样饱和，grad ≈ 1e-3；
- 直接加大 `λ_D` 到 800 而不换代理：只是把位移放大，风险不一定下降。

## 5. 正式实验（20 个冻结任务）

### 5.1 方法定义

| 方法 | 几何 | 时间 |
|---|---|---|
| G0 | 冻结 MPD 轨迹 | 原始等待 |
| G2 | 重新采样（仅官方 SDF），B=1，**不筛选** | 原始等待 |
| G3 | 重新采样（SDF + First-Hit 引导），B=8，**同一筛选** | 原始等待 |
| G5 | 重新采样（仅官方 SDF），B=8，**同一筛选** | 原始等待 |

**公平性关键**：G3 与 G5 使用**完全相同**的候选选择程序
（beam search，宽度 4，先保 p=0 安全再最小化风险），
唯一区别是候选池是否在 DDIM 里接了 First-Hit Guide。
G2 与 G3/G5 的池使用**同一扩散种子**。

### 5.2 主结果表

| 方法 | 有效率 | 静态安全 | 速度合规 | p=0 安全 | 碰撞 p=0.1 | 安全完成 p=0.1 | 碰撞 p=0.2 | 轨迹长度 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| G0 冻结 | **1.00** | 1.00 | 1.00 | 1.00 | 55.74% | 44.26% | 71.67% | 8.49 m |
| G2 原始采样 | 0.00 | 0.85 | 0.70 | 0.00 | 99.91% | 0.09% | 99.87% | 12.87 m |
| **G3 引导+筛选** | **0.40** | **0.90** | 0.65 | 0.85 | **46.05%** | **53.95%** | **63.09%** | 12.07 m |
| G5 SDF+筛选 | 0.20 | 0.60 | 0.65 | 0.80 | 55.28% | 44.72% | 70.24% | 12.49 m |

（p=0.1、p=0.2 全为 3 种子 × 200 次 MC 的平均；p=0 行是硬判据。）

### 5.3 G3 vs G5：几何引导的净贡献

| 指标 | G5 | G3 | 差值 |
|---|---:|---:|---:|
| 碰撞率 p=0.1 | 0.5528 | 0.4605 | **−9.23 pp** |
| 碰撞率 p=0.2 | 0.7024 | 0.6309 | −7.15 pp |
| 安全完成率 p=0.1 | 0.4472 | 0.5395 | +9.23 pp |
| 联合有效率 | 0.20 | 0.40 | **+20 pp** |
| 静态安全率 | 0.60 | 0.90 | +30 pp |
| 轨迹长度 | 12.49 m | 12.07 m | −0.42 m |
| makespan p=0.1 | 43.65 | 43.62 | −0.03 |

**在完全相同的选择程序下，引导池比 SDF 池好 9.2 pp 碰撞率、2 倍有效率。**
这是本次唯一稳定的正向结论。

### 5.4 与最强纯时间基线的差距

| 方法 | p=0.1 碰撞率 | p=0.2 碰撞率 |
|---|---:|---:|
| G1 = 冻结库 + W2+@800 | **4.45%** | 35.77% |
| G0 = 冻结库 + 原始等待 | 55.74% | 71.67% |
| G3 = 引导几何 + 原始等待 | 46.05% | 63.09% |

**几何引导 + 原始等待（46.05%）仍远差于冻结库 + W2+（4.45%）。**

原因不是引导无效，而是**规划覆盖率**：本方案的联合有效率只有 40%，
而冻结库是 100%；把几何换成 40% 有效的方案，再好也无法与 100% 有效的方案比。

## 6. 其它必须报告的观察

### 6.1 原始采样几乎不产生合法联合计划

G2 的 p=0 安全率是 **0%**，静态安全 85%，速度合规 70%。
4 台机器人独立从单机器人模型采样，路径常常直接重叠（同刻间距 < 0.35 m）。
这说明**多机器人联合生成本身是瓶颈**，而不是几何引导不够强。

### 6.2 轨迹变长

重采样几何平均 12.1–12.9 m，冻结库是 8.49 m（**+42%**）。
引导把路径推开是有代价的，且速度合规率从 100% 降到 65%（重采样后段长 > 0.6 m 的情况变多）。

### 6.3 静态安全反而更好

G3 的静态安全率 90% > G5 的 60%。这是一个意外结果：
引导的 SDF 项与 First-Hit 项共同作用时，轨迹更容易避开障碍——
但样本量小（20 任务），也可能是 beam 选择顺序的偶然结果，不能过度解读。

### 6.4 引导是否被后续去噪抹掉

`guide_traces.json` 记录了每次 Guide 调用的 `soft_risk / hard_risk / hinge_gap /
grad_norm / loss`。观察：

- 每次调用梯度都非零（末次 `grad_norm` 在 0.3–3 之间）；
- 但 `hard_risk` 在后续去噪步中会部分回升——
  即"当步修正有效、下一步被抹掉"的现象**确实存在**，与历史问题 D 一致；
- 本方案用"后期引导 + 每步 10 次更新"缓解，未彻底解决。

### 6.5 计算开销

| 项 | 耗时 |
|---|---:|
| 一次 4 机器人 × 8 候选的 DDIM 采样（无引导） | ≈ 8 s |
| 同上 + First-Hit 引导（10 guide steps/步） | ≈ 14 s（+75%） |
| 20 任务全流程（G0/G2/G3/G5 + MC） | 12.0 min |

## 8. 最终回答六个问题

| # | 问题 | 回答 |
|---|---|---|
| 1 | First-Hit 几何引导能改变扩散轨迹吗？ | **能**。同种子配对位移 0.17–0.29 m（最大 1.4 m），梯度非零，方向经有限差分验证 |
| 2 | 几何 + 等待是否优于最强纯等待 W2+？ | **没有证据支持**。G3（46.05%）远差于 W2+（4.45%）；G4 未完成 |
| 3 | p=0.2 下碰撞率降低多少？ | 相对 SDF 池：70.24% → 63.09%（−7.15 pp） |
| 4 | 收益的代价？ | 轨迹 +42%、速度合规 100%→65%、每任务规划 +75% |
| 5 | 真 DDIM 引导 vs 候选重排序？ | **引导更好**（−9.23 pp，有效率翻倍），但两者都远不如冻结库 |
| 6 | 是否值得作为论文核心方法？ | **暂不足以**。可作为"扩散过程内可微风险引导可行且有正收益"的方法学证据 |

### 论文价值判断

**可以支持的表述**：
- 在**同一候选选择程序**下，把 First-Hit 风险梯度接进 MPD 的 DDIM 引导，
  比纯 SDF 引导显著降低多机器人延迟碰撞率（46.05% vs 55.28%），并提高联合有效率（40% vs 20%）；
- 首次碰撞概率在路径重叠时**梯度饱和**，必须配合非饱和几何代理才能驱动去噪——
  这是一个对后续工作有参考价值的方法学结论。

**不能支持的表述**：
- "几何引导解决了多机器人延迟鲁棒问题"——差距是数量级的；
- "几何 + 等待优于纯等待"——G4 未做。

**下一步建议（按优先级）**：
1. **补 G4/G7**：保存几何路径，对 G3 施加 W2+，做 1–3 轮交替优化；
2. **提高联合规划覆盖率**：当前真正的瓶颈是 40% 的有效率。
   可考虑"逐对增量构造 + 引导生成"的混合方案（用引导改善候选质量，用组合搜索保证 p=0 安全）；
3. 在覆盖率问题解决前，**不建议**进入底层 MPC 执行验证。
