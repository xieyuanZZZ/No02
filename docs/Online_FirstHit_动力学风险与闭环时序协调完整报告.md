## 2. P0：MPC 与评测修复（已完成）

### 2.1 预测矩阵（数学错误，已修复）

`_build_prediction()` 原实现为：

```python
G[4k:4k+4, 2j:2j+2] = A^(k-j) @ B     for j in 0..k        # 错
```

正确关系是

```
x_k = A^k x_0 + Σ_{j=0}^{k-1} A^{k-1-j} B u_j
```

两处错误：**幂次多乘了一个 A**、**把 u_k 混进了 x_k**（导致 `x_0` 依赖 `u_0`）。

修复后独立验证（随机 `x0`、随机 `U`，5 组）：

```
max |F x0 + G U − 逐步仿真| = 1.7e-16
```

回归测试 `test_prediction_matrix_matches_stepwise_simulation` 与
`test_x0_does_not_depend_on_u0` 已加入。

> 这条修复会改变所有 MPC 结果。旧结果（`d067f3c`）中的 MPC 数值**不可再引用**。

### 2.2 等待执行逻辑（已修复）

原实现的问题与修复：

| 问题 | 原行为 | 现行为 |
|---|---|---|
| 等待计时起点 | 进入 HOLDING 即开始计时（此时还没停稳） | **速度 < 0.03 m/s 后才开始计时** |
| 制动时间 | 混在等待里 | 单独累计 `extra_brake_time`，不重复计入 |
| 停车点 | 距离 < 0.25 m 就算到达 | 制动目标**就是该航点弧长**，不允许提前经过 |
| 刹不住 | 静默继续 | 标记 `infeasible_stops`，不悄悄跳过 |
| 暂停时长 | 从请求时刻起算 | 从**停稳时刻**起算 |

回归测试 `test_dwell_starts_only_after_full_stop` 断言：
在航点 20 停 0.8 s 的计划，实测 `held = 0.8 ± 0.12 s`，且停稳时刻速度接近 0。

### 2.3 碰撞统计（已修复）

`SimResult` 新增每对字段（N=4 共 6 对）：

```
pair_collision[P], pair_first_time[P], pair_min_distance[P], pairs
```

外加全队的 `collision / first_collision_time / first_collision_pair`。
`firsthit_mpc_mismatch.py` 改为直接使用 `pair_collision` 计算两两频率，
不再用"全队首次碰撞"近似。

### 2.4 跟踪误差（已修复）

即使 `record=False`，执行器也在线累计：`err_sum_sq / err_max / n_steps`、
`speed_max / accel_max / s`。实测 RMSE **0.012–0.020 m**（旧版显示为 0 是记录缺失）。

### 2.5 随机暂停事件（已修复）

新增 `make_pause_events(seed, p, n_robots, n_slots, cfg)`：**预先**生成
`[(slot, robot, duration)]`，与调度方法无关。测试 `test_pause_events_are_method_independent`
断言同种子完全相同、换种子不同。

执行器记录：请求 / 是否被接受 / 制动开始 / 停稳 / 恢复 五类时间戳。

### 2.6 p=0 安全性复核

| 组 | 碰撞任务数 | 最小对间距 |
|---|---|---|
| N=2 | **0 / 6** | 0.544 – 2.272 m |
| N=4 | **1 / 6** | **0.343 m**（d_safe = 0.35） |

**N=4 的这 1 个碰撞是物理余量问题**：冻结库在离散模型下的 p=0 最小间距是 0.355 m，
只比 `d_safe` 高 5 mm；MPC 的连续运动把 0.343 m 吃到阈值以下（差 7 mm）。
这是真实的"执行侵蚀安全余量"，**没有通过增加等待去掩盖**，按实施安排要求记录在案。

## 3. P1：修复后的可信基准（已完成）

**设置**：N=2 取 8 个任务、N=4 取 8 个，p ∈ {0, 0.1, 0.2}，每格 **6 次** MC，
同一任务/同一等待计划/同一事件序列配对。总耗时 9.6 min。

### 3.1 碰撞率

| 组 | 计划 | p=0 理想 → MPC | p=0.1 理想 → MPC | p=0.2 理想 → MPC |
|---|---|---|---:|---:|
| N=2 | 原始 | 0.0% → 0.0% | 6.2% → **18.8%** | 4.2% → **16.7%** |
| N=2 | W2+ | 0.0% → 0.0% | 0.0% → **10.4%** | 0.0% → **22.9%** |
| N=4 | 原始 | 0.0% → **12.5%** | 56.2% → **75.0%** | 75.0% → **93.8%** |
| N=4 | W2+ | 0.0% → **25.0%** | 2.1% → **56.2%** | 37.5% → **64.6%** |

### 3.2 安全完成率与完成时间

| 组 | 计划 | p=0.1 理想 → MPC | 完成时间（p=0.1 / p=0.2） |
|---|---|---|---|
| N=2 | 原始 | 93.8% → 81.2% | 19.8 s / 26.1 s |
| N=2 | W2+ | 100% → 89.6% | 20.6 s / 27.0 s |
| N=4 | 原始 | 43.8% → 25.0% | 22.9 s / 29.7 s |
| N=4 | W2+ | 97.9% → 43.8% | 25.0 s / 31.0 s |

### 3.3 关键结论（阶段目标）

**修复后 W2+ 在 MPC 下还能降低多少碰撞率？**

| 组 | p | 原始 → W2+（MPC） | 降低 |
|---|---:|---|---:|
| N=2 | 0.1 | 18.8% → 10.4% | **−8.4 pp** |
| N=2 | 0.2 | 16.7% → 22.9% | **+6.2 pp（变差）** |
| N=4 | 0.1 | 75.0% → 56.2% | **−18.8 pp** |
| N=4 | 0.2 | 93.8% → 64.6% | **−29.2 pp** |

**W2+ 在 MPC 下仍然有效，但收益大幅缩水**：N=4 p=0.1 时理想模型里是 −54 pp，
MPC 里只有 −18.8 pp。**在 N=2、p=0.2 时 W2+ 甚至变差**——因为它的等待是
在离散模型下调出来的，MPC 的制动/加速额外时间把实际时序推离了最优点。

**理想模型与 MPC 之间是否显著失配？** **是**，而且比修复前更清楚：

| 对照 | MAE | 偏差 | ρ |
|---|---:|---:|---:|
| DP vs 理想 MC | 0.0456 | +0.0065 | 0.771 |
| DP vs **MPC** MC | **0.1021** | **−0.0560** | 0.654 |
| 理想 MC vs MPC MC | 0.1089 | −0.0625 | 0.544 |

DP 对理想模型仍然准（MAE 0.046，与修复前的 0.041 同量级，说明 DP 实现没问题）；
但对 MPC **系统性低估 5.6 pp**，且 p 越大偏差越大（p=0.1 的 MAE 0.070，p=0.2 的 0.135）。

## 4. P2：M0 / M1 / M2 风险模型对比（已完成）

### 4.1 先给 DP 加段时长接口


elease_times_with_durations(wait, durations)：

    tau_m = (到达航点 m 的累计通行时间) + sum_{h<=m} w_h

durations 默认全 1 时**与原模型完全一致**（有测试保证），因此这是纯扩展，
不改首次碰撞 DP 的数学结构。

### 4.2 一个关键的前置观察

p=0 时实测的段通行时间中位数是 **1.000 时隙**——因为时间参数化里的计划速度上限
让机器人精确贴合原调度表。所以**用 p=0 的数据做 M1 会退化为 M0**，
段时长修正必须在**有暂停**的运行上标定。

### 4.3 三个模型

| 模型 | 说明 |
|---|---|
| M0 | 原始 First-Hit，每段恒 1 时隙 |
| M1 | 用 MPC 实测的**平均**段通行时间替换 1 时隙 |
| M2 | 用实测段时长的**经验分布**做自举采样（每段独立抽一个值），跑 24 次 DP 取平均风险 |

校准/测试分离：前一半任务只用于采集时长（不含碰撞信息），后一半任务做测试。

### 4.4 结果（8+8 任务，12 次 MC，p ∈ {0.1, 0.2}，112 个机器人对）

| 模型 | MAE | 偏差 | RMSE | Spearman ρ |
|---|---:|---:|---:|---:|
| M0 原始 | 0.1235 | −0.0589 | 0.1908 | 0.622 |
| M1 均值时长 | **0.1570** | −0.0762 | 0.2325 | **0.541** |
| **M2 分布采样** | **0.1182** | +0.0544 | **0.1808** | **0.651** |

分组：

| 组 | M0 MAE / ρ | M1 MAE / ρ | M2 MAE / ρ |
|---|---|---|---|
| N=2 | 0.0575 / 0.277 | 0.0528 / 0.259 | **0.1116 / 0.230** |
| N=4 | 0.1345 / 0.637 | 0.1743 / 0.604 | **0.1193 / 0.690** |

### 4.5 结论

1. **M1（均值修时间）失败**：MAE 反而变差 27%，排序相关从 0.622 掉到 0.541。
   这说明失配**不是时间尺度问题**——把每段拉长反而破坏了相对时序。
2. **M2 只在 N=4 有效**：MAE −11%、ρ +8%；在 N=2 反而明显变差（0.058 → 0.112）。
3. **M2 的偏差方向变了**：从 M0 的 −5.9 pp（低估）变成 +5.4 pp（高估），
   说明用分布采样会放大风险，需要额外校准。
4. 总体提升 **有限**（MAE −4.3%、ρ +4.7%），**不足以单独支撑一篇论文的方法贡献**。

**为什么 M2 提升有限**：它只改进了每段耗时的分布，但真实的失配还来自
**暂停发生在哪一段**（位置相关）和**制动/重启的模式切换**，
这两点需要状态相关模型（原计划的 M2 完整版），本轮没有实现。

## 7. 与论文创新的关系（当前判断）

- **可以说**：理想离散执行模型会**系统性低估**真实动力学下的碰撞风险（−5.6 pp），
  并显著高估调度收益（N=4 的 W2+ 收益从 −54 pp 缩到 −18.8 pp）。这是有实验支撑的观察。
- **不能说**：动力学感知 First-Hit 有效、在线协调有效——**这两项本轮没有数据**。
- 因此当前**不足以**作为期刊论文的方法部分，只能作为"问题定义 + 失配证据"。
