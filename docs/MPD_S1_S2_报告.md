## 1. 阶段一：冻结的有效轨迹库

### 1.1 流程

```
官方 MPD（预训练权重 + SDF 引导）
   └─ 每机器人 8 条原始候选（448 条）
        └─ 本仓库逐条独立审计（米制、连续几何）
             └─ 369 条通过（82.4%）
                  └─ 两两组合成 33 对联合任务
                       └─ 24 对在 p=0 下无碰撞且全部到达 → 入库
```

生成侧：`mpd_extension/gen_plan_candidates.py`（WSL / mpd 环境，官方 MPD 库）。
审计与组库侧：`scripts/mpd_s1_build_plan_bank.py`（主环境，python3.12）。

### 1.2 对"历史问题"的处理（实施安排 §2）

| 历史问题 | 本批做法 |
|---|---|
| `q_trajs_pos_valid` 已被官方筛选，不是原始轨迹 | 落盘**两条**：`pos_raw`（全部 8 条）+ 官方有效 mask；并**重算** `get_trajs_unvalid_and_valid` 拿到 `valid_idxs` |
| 官方筛选只查关节/速度/加速度，**不查静态碰撞** | 已实测：440 条"官方有效"里有 79 条撞静态障碍（17.9%）。审计 CSV 里逐条记录 |
| 10 m 地图与 [-1,1] 坐标不统一 | 生成侧同时落盘官方坐标与米制；**所有检查都在米制下做** |
| 只查离散点会漏碰撞 | 用 128 个采样点做连续距离检查，并给出 **弦误差上界** `max‖q̈‖·h²/8`，要求 `min_clearance > 上界` |
| 128 轨迹点 ≠ 96 执行时隙 | 按**弧长**重采样到 H=32 航点，执行模型每时隙推进一个索引；映射关系与测试见 §1.4 |
| 联合任务不能只看单机可行 | 组合后用 `simulate_execution` 做 p=0 联合检查，不通过就丢弃 |

### 1.4 时轴映射（必须写清的部分）

| 概念 | 取值 | 说明 |
|---|---|---|
| MPD 轨迹 | 128 点 / `trajectory_duration=10.0 s` | 只作为**几何**来源 |
| 执行航点 | H = 32 | 由 MPD 曲线按**弧长**均匀重采样 |
| 执行时隙 | T = 96，Δt = 0.4 s | 每时隙推进一个航点索引，段内线性插值 |
| 速度约束 | 每段 ≤ v_max·Δt = 0.6 m | 重采样后逐段检查 |
| 发车间隔 | 固定 3 个时隙/台 | 写入 `baseline_wait`，所有方法共用 |
| 无等待完成时隙 | 31 + 3·i | 测试 `test_stagger_shifts_completion_by_expected_slots` 锁定 |

**MPD 的 10 s 物理时长不进入执行模型**——执行模型只吃几何路径与航点推进。
这一点在报告里显式声明，避免"128 点 = 96 时隙"的误用。

## 2. 阶段二：随机暂停的碰撞验证

### 2.1 设置

- 轨迹、发车间隔完全不变，只加逐步随机暂停；
- p ∈ {0, 0.05, 0.1, 0.2}，每格 **400 次**蒙特卡洛，共 24×4×400 = 38,400 次执行；
- 筛选种子 `20261104`（**不用于正式评测**）；
- 碰撞判据：d_safe = 0.35 m，连续段几何。

### 2.2 结果

| p | 碰撞率 | 安全完成率 | 全部到达率 | makespan（时隙） |
|---:|---:|---:|---:|---:|
| 0.00 | **0.000** | 1.000 | 1.000 | 34.0 |
| 0.05 | 0.0497 | 0.950 | 1.000 | 35.7 |
| 0.10 | 0.0864 | 0.914 | 1.000 | 37.6 |
| 0.20 | 0.1289 | 0.871 | 1.000 | 42.4 |

- **p=0 完全无碰撞**，与阶段一一致；
- 碰撞率随 p 单调上升，makespan 从 34.0 增到 42.4（+24.7%）；
- 全部到达率始终 1.0——碰撞并不妨碍到达，说明是"穿过对方"

### 2.3 First-Hit Risk DP 与蒙特卡洛对照

| 指标 | 值 |
|---|---:|
| 相关系数 | **0.998** |
| 平均绝对误差 | **0.0044** |
| 样本点数 | 96（24 任务 × 4 个 p） |

DP 预测与 MC 高度一致，说明状态转移、时隙数、边界与碰撞判据是自洽的。
**这一项通过后，才允许用 DP 做梯度优化（阶段三）。**

### 2.4 任务分组（筛选种子，已冻结）

| 组 | 判据（p=0.1 碰撞率） | 任务数 |
|---|---|---:|
| 延迟不敏感 | < 0.02 | 14 |
| 轻度敏感 | 0.02 – 0.2 | 7 |
| **高度敏感** | ≥ 0.2 | **3** |

任务 ID 已写入 `task_freeze.json`。**正式评测必须换一组评测种子**，避免"用筛选种子挑任务再评测"的循环论证。

### 2.5 验收

| 条件 | 结果 |
|---|---|
| p=0 与阶段一一致 | ✅ 0.0000 |
| 存在足够"无延迟安全、延迟下碰撞"的任务 | ✅ 10/24（42%）在 p=0.1 时 >2% |
| 硬风险预测与 MC 趋势相符 | ✅ r=0.998，MAE=0.0044 |

## 4. 遇到的问题

| # | 问题 | 处理 |
|---|---|---|
| 1 | 官方"有效"轨迹其实会撞静态障碍 | 加独立连续几何审计（79/440 被拒） |
| 2 | B 样条只查离散点可能漏碰撞 | 用 `max‖q̈‖·h²/8` 作为弦误差上界，并要求净空大于该上界 |
| 3 | MPD 时长（10 s / 128 点）与执行时隙（96×0.4 s）不同 | 只取几何、按弧长重采样到 32 航点；写测试锁定时轴 |
| 4 | 联合任务可能"单机可行但联合撞" | p=0 联合仿真筛选，33 对里淘汰 9 对 |
| 5 | 弦误差上界对抛物线恰好取等，浮点比较失败 | 测试加 1e-12 容差 |

## 5. 结论与下一步

**结论**：已经具备开展"仅等待优化"实验的可靠基础。
延迟冲突确实存在（p=0.2 时 12.9%）、DP 预测可信（r=0.998）、任务集已冻结。

**下一步（阶段三）**：
1. 冻结几何，只优化等待变量 w；
2. 基线：W0 原计划不调整、W1 固定裕度/优先级等待、W2 First-Hit Risk 优化等待；
3. 正式评测换用**独立评测种子**，报告全部 24 个任务 + 10 个敏感子集；
4. 指标：安全完成率、碰撞率、超时率、makespan、新增等待、优化耗时。
