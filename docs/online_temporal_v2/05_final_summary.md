## 1. 修改了什么

1. **修复简单在线**（`src/fhd/optim/online_baseline.py`）：
   - 不再用恒相等的“当前位置中点”判断谁更远；
   - 在预测危险时刻保留每台机器人**自身路径**上的冲突弧长；
   - 用“沿路径剩余距离 / 名义速度”算 ETA，让较晚到达者让行；
   - 仅 ETA 平局时用机器人编号；
   - 停车点必须早于冲突区且满足制动距离；
   - 首选方不可停时检查另一方，双方都不可停则记录无解；
   - 动作前做轻量全队前瞻，拒绝制造新冲突；
   - 计划等待结束后恢复前进，不再“到等待点永久静止”；
   - p=0 不做在线动作，避免把安全计划改成新碰撞；保留 cooldown/最长等待/冲突记忆。
2. **组合方法**：`offline_plus_firsthit` = 离线 W2+ 等待计划 + 执行期当前状态条件化
   First-Hit 在线修正；只追加等待，不删除离线等待。
3. **评测**：五种方法统一在 `scripts/online_temporal_benchmark.py` 中配对，
   同路径、同 MPC 参数、同 `d_safe`、同预生成事件表、同 `dt_slot=0.4 s`。
4. **测试**：新增 ETA/ID 平局/停车点/前瞻/恢复/p=0/组合语义测试；全量 **236 passed**。
5. **未做**：没有新 M1/M2/M3、没有改 Diffusion、没有几何重规划、没有改路径/阈值/MPC 参数。

## 3. 核心结果

### 20 任务（10 seeds）机器人间碰撞率

| 方法 | p=0.05 | p=0.1 | p=0.2 |
|---|---:|---:|---:|
| 原始等待 | 0.600 | 0.750 | 0.775 |
| 离线 W2+ | 0.210 | 0.310 | 0.530 |
| 修复后的简单在线 | 0.540 | 0.735 | 0.820 |
| First-Hit 在线 | 0.080 | 0.105 | 0.195 |
| **离线 W2+ + First-Hit 在线** | **0.035** | **0.050** | **0.120** |

### 混合方法 vs 离线 W2+（20 任务）

- p=0.05：碰撞 **−17.5 个百分点**，区间 [−26.5, −9.5]；
- p=0.1：**−26.0 个百分点**，区间 [−36.0, −17.0]；
- p=0.2：**−41.0 个百分点**，区间 [−50.5, −32.5]；
- 代价：完成时间 +0.33 / +0.67 / +1.27 s，总等待 +0.31 / +0.59 / +1.23 s；
- 在线等待只有 0.31 / 0.64 / 1.29 s，说明不是“无限等待换安全”；
- 决策 P95 9.2 / 13.6 / 17.4 ms，全部低于 400 ms。

### 简单在线

修复后在 p=0 与原始计划完全一致（0 动作、0 新碰撞）；但 20 任务上
p=0.05/0.1 的安全增益不显著，p=0.2 甚至略差于原始（+4.5 pp，区间 [0,+9.5]）。
**简单在线是正确但弱的基线，不能替代 First-Hit。**

## 4. 失败与边界

- 混合方法在 20 任务中有 **4 个**“离线安全、混合碰撞”配对，另有 **183 个**
  “离线碰撞、混合安全”；它不是安全保证。
- 37 个配对两者都碰撞：时序调整不能解决所有几何/静态障碍问题。
- 20 任务包含 6 个 `single_obstacle` 任务，静态障碍碰撞率约 **25.75%**，
  所有方法相同；冻结路径本身穿入障碍，必须单列，不能算作在线方法失败或成功。
- 简单在线修复后仍有 77 个“简单碰撞、原始安全”配对（8 任务）——策略太弱，
  不是 bug 完全解释得了的；不应继续靠调参把它“调到优于”目标方法。
- 没有通信延迟、提前恢复、滚动窗口、N=2/N=6；没有 50-seed 最终统计。

---

## 5. 研究取舍

- **继续在线 First-Hit**：它是有效信号，单独就显著优于离线和简单在线；
- **采用“离线 W2+ + 在线 First-Hit”作为当前最佳组合**：20 任务方向一致，
  碰撞显著下降，额外等待/时间很小；
- **停止扩展简单在线**：它适合作为负基线/对照，不应作为主方法；
- **不要增加复杂融合模块**：下一步应先做“门控 + 恢复相位建模”，减少那 4 个
  “破坏离线安全计划”的失败，而不是加新网络；
- **在写论文前补 50 seeds**，并把静态障碍与机器人间碰撞分开报告；
- 不建议现在转向新的 M1/M2/M3 或几何重规划；本轮问题已经有明确正结果。
