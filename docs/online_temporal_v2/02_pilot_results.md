# 02 原冻结任务公平复测：修复后的简单在线 vs 离线

**日期**：2026-11-05  
**分支**：`experiment/online-temporal-evaluation-v2`  
**结果**：`results/Online_Temporal_v2/01_pilot/`  
**设置**：8 个 N4 冻结任务（`open_crossing_300000/300003/300006/300009` 各 2 个），
p∈{0,0.05,0.1,0.2}，每格 30 个事件种子；5 种方法共用同一路径、MPC 参数、
`d_safe=0.35`、预生成随机暂停事件表、`dt_slot=0.4 s`。共 **4,800 条 run**，
总耗时 **62.7 min**。

方法名：

- `raw_wait`：原始等待，不做在线调整；
- `offline_w2plus`：离线整数搜索 W2+，执行期不调整；
- `simple_online_fixed`：修复后的简单在线冲突预测 + 固定优先级让行（原始等待起点）；
- `firsthit_online`：当前状态条件化 First-Hit 在线等待（原始等待起点）；
- `offline_plus_firsthit`：离线 W2+ + First-Hit 在线修正（阶段三组合）。

**配对差（vs raw_wait）**：

| p | 碰撞差 | 95% 任务级区间 | 安全完成差 |
|---:|---:|---|---:|
| 0 | 0.000 | [0, 0] | 0.000 |
| 0.05 | +0.012 | [−0.133, +0.179] | −0.012 |
| 0.1 | **−0.071** | [−0.163, +0.050] | +0.071 |
| 0.2 | +0.008 | [−0.037, +0.054] | −0.008 |

**结论**：简单在线修复后**不再依赖 ID 假象**，p=0 完全退化为原始计划（0 次在线动作，
0 新碰撞），停车命令全部通过执行器可行性检查（2,293/2,293 接受，0 拒绝）。
但它在 p=0.05/0.2 与 raw_wait 基本持平、p=0.1 只有约 7 pp 的非显著改善，
**没有形成可信的安全增益**。这是一个正确的、但性能弱的简单基线，不能作为“简单方法已经够用”的证据。

**为什么弱**：简单规则只看短时名义冲突，选中一个停车点就停 0.4 s；它无法判断
“停一次是否足以错开整个冲突窗口”，也不能像风险 DP 那样比较多种等待位置。
本报告保留这个负结果，不把简单方法继续调参到“刚好优于”目标方法。

## 2. 与 First-Hit 在线方法的对照

| 对照 | p=0.05 | p=0.1 | p=0.2 |
|---|---:|---:|---:|
| First-Hit − 简单在线（碰撞） | −0.575 [−0.742,−0.429] | −0.608 [−0.717,−0.496] | −0.642 [−0.713,−0.562] |
| First-Hit − 简单在线（安全完成） | +0.575 | +0.608 | +0.642 |
| First-Hit − 简单在线（完成时间） | +0.67 s | +1.11 s | +1.89 s |

First-Hit 在线显著更安全，但每任务多约 0.7–1.9 s 完成时间；这部分是阶段三组合的输入。

## 3. 旧结果的关系

- 旧 `results/Online_Temporal/03_ab_comparison/` 的简单在线是**未修复版本**，
  其 p=0.1 碰撞 0.642、p=0.2 0.796；
- 修复后简单在线 p=0.1 0.696、p=0.2 0.829，**并没有因为修 bug 而变好**；
  这说明旧版简单在线的主要问题不是唯一的“中点错误”，而是策略本身太弱；
- 旧报告的 8 任务/30 seeds 与本次同任务/同种子，但旧版代码不可与新结果混合统计。
  旧结果完整保留，不覆盖。

## 4. 失败与限制

- 简单在线有 **77 个**“简单碰撞、raw 安全”配对，同时有 **89 个**“简单安全、raw 碰撞”；
  净收益小且不稳定，不能据此宣称在线有效。
- 没有 timeout、没有 MPC 失败、没有不可行停车；所有在线命令被接受。
- 8 个任务不足以支撑最终结论；20 任务扩展见 `04_scale_status.md`。
- 静态障碍未纳入本轮；本组任务路径不触发障碍碰撞。
