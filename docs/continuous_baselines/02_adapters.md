# 02 连续基线适配器状态

**日期**：2026-11-06  
**原则**：不修改冻结的 First-Hit、离线 W2+、联合协调、Diffusion、MPC 执行器、
路径、数据和旧结果。适配器只做输入/输出转换。

---

## 1. 已实现

### MMD 路径导入适配器

`src/fhd/adapters/mmd_adapter.py`

- 输入：MMD 官方推理导出的中性 JSON（`agents`: [N,T,4] `[x,y,vx,vy]`）；
- 输出：No02 冻结格式 `[N,32,2]`，按弧长等距重采样；
- 校验：起终点是否保持、resample 是否移动端点、路径数/H 是否正确；
- 保留原生 planning time 和原始轨迹，实验 B 可把规划时间与执行时间分开；
- 测试：`tests/test_continuous_adapters.py`（3 项通过）。

**边界**：这只是把 MMD 的轨迹接入统一执行器；没有给 MMD 加 No02 在线等待，
也没有把它当成固定路径在线协调方法。

---

## 2. 未完成适配及具体原因

### Coordination ORU

- 官方三机器人示例已跑通（见 `01_reproduction.md`）；
- 其核心输出是 Java 协调器中的 precedence/critical-section/stop 决策，不是可直接
  注入 No02 的动作序列；
- 需要写 Java→Python/JSON bridge，并在每个 No02 `dt_slot` 将“谁在哪个 critical
  section 前等待”映射为 `request_stop_at`；同时保留其动态优先级和在线让行；
- 尚未完成；不能用它的“运行日志”冒充 No02 碰撞率。

### ORCA / RVO2

- 官方 Circle 示例已跑通；
- RVO2 输出的是**每步期望速度**，No02 执行器是双积分 MPC，不能瞬时改速度；
- 需要新增“ORCA 速度 → 加速度受限速度跟踪”的适配器，并统计相对参考路径偏离；
- 这不是改 RVO2 核心，但需要独立控制器；尚未实现。

### MPC-CBF

- 官方示例已跑通，但它是 **2 机器人差速驱动** MPC-CBF；
- 任务书要求四机器人双积分器；直接套用会改变动力学和被控对象；
- 需要把 CBF 约束移植到统一双积分动力学，并重新验证可行性与安全性；
- 本轮没有把 2 机器人差速结果当成 4 机器人结果。

## 3. 进入 S3 前必须通过

1. 每个适配器在 2 个 N4 任务、p=0.1、3 个种子上 smoke；
2. 输入单位/坐标/时间步与 No02 一致；
3. 原方法动作不被静默丢弃，拒绝原因可统计；
4. 相对参考路径偏离、在线计算时间、不可行停车/死锁/超时均记录；
5. 与冻结离线+First-Hit 方法使用同一路径、事件表、碰撞判定和种子。
