# 06 闭环验证：多机器人 MPC-CBF

**日期**：2026-11-06  
**结果**：`results/Continuous_Baseline_Comparison/pilot/mpc_cbf/`

## 实现

`src/fhd/adapters/mpc_cbf_adapter.py` 是独立控制器，不调用冻结 No02 MPC：

- 双积分器状态 `[x,y,vx,vy]`，控制 `[ax,ay]`；
- 滚动时域 4 步，`dt=0.1 s`；
- 硬约束：`|v|<=1.5`、`|a|<=2.0`；
- 每对机器人、每个时域点加入离散 CBF：
  `||p_i-p_j||²-d_safe² >= ...` 的离散形式
  `h_{k+1} >= (1-gamma) h_k`，`gamma=0.1`；
- 参考路径的 lookahead 目标作为跟踪项；
- IPOPT 求解；失败/不可行显式计数；
- 随机暂停：暂停机器人期望目标保持当前状态，实际速度受加速度限制。

**未使用**官方 2 机器人差速模型；这是按任务要求实现的双积分多机器人版本。
它保留 MPC-CBF 的滚动优化 + 硬 CBF 约束思想，但不是官方差分驱代码的直接移植。

## N2/N4 最小闭环

| 场景 | 任务 | p | 碰撞 | 安全完成 | 到达 | 完成 | IPOPT 失败 | 求解 mean/P95 |
|---|---|---|---:|---:|---:|---:|---:|---:|
| N2 | `open_crossing_300000_pair02_11` | 0.1 | 1 | 0 | 是 | 7.5 s | 0 | 20.8 / 23.3 ms |
| N4 | `open_crossing_300000_n4_0` | 0.1 | 1 | 0 | 是 | 9.9 s | 0 | 53.7 / 59.9 ms |

**两例都发生机器人间碰撞（最小间距 0.0）**，说明当前 CBF 实现/目标推进仍不正确。
不能把“IPOPT 成功”当作安全成功。可能的错误包括：

- 用最近路径点推进 `idx`，在交叉路径上可能跳过目标/错误推进；
- 硬 CBF 约束只覆盖时域点，控制器在到达后提前终止；
- 目标 lookahead 与路径几何不一致。

因此 MPC-CBF 目前只达到“独立可运行”，**不满足闭环公平对比条件**，不进入正式实验。

## 下一步

- 对 N2 先做到无碰撞，再扩 N4；仍不可行时报告具体约束冲突，而不是取消 CBF。
