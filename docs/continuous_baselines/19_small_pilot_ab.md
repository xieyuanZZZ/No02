# 19 小规模 A/B 验证（去掉狭窄场景）

**日期**：2026-11-14  
**结果**：`results/Continuous_Baseline_Comparison/credible_v1/small_pilot_ab/`

## 改动

1. 去掉 C 狭窄场景，只保留：
   - A1/A2 开阔非共线交叉；
   - B1/B2 静态障碍。
2. 修复 W2+ 的零等待退化：
   - `require_p0=True` 仍是默认，冻结旧行为不变；
   - 实验使用 `require_p0=False, p0_weight=1.0, initial_stagger=True`；
   - 允许从已有冲突的初始方案开始优化，而不是直接 fallback。
3. A1 实际 W2+ 输出：`[3,0,0,7]` 个时隙，hard risk 从 0.908 降到 0.026。
4. 统一评价器区分实体接触与 0.35 m 安全距离。

## 规模

4 任务 × p=0（1 seed） + p=0.1（2 seeds） × 3 方法 = **36 条记录**。

## 关键解释

- **Ours 从 0/0.667 提升到 A/B 全部安全完成**；
- 提升来自 W2+ 真正产生入口等待，而不是调 MPC 或降低安全阈值；
- MPC-CBF 开阔场景也 1.0，但静态场景只有 0.667；
- **ORCA 的 0 不能当成算法失败**：其轨迹停在终点前约 0.37–0.42 m，
  C++ runner 的目标完成阈值与统一评价器 0.25 m 不一致，导致
  `all_arrived=false`；这是适配器到点判定问题，不是 ORCA 避碰能力差。

## 结论

- 修复 W2+ 后，Ours 在 4 个 A/B 任务、p=0/0.1 上达到 100% 安全完成；
- 与 MPC-CBF 相比：开阔相同，静态障碍 Ours 更好；
- 与 ORCA 暂时不能下结论，必须先修 ORCA 到达阈值；
- 本轮没有把 ORCA 的失败当作 Ours 的优势，也没有修改 ORCA 避碰能力。
